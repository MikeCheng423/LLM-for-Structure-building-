# Journal-to-ASE Catalyst Structure LLM

## 1. Project goal

Build a Qwen 4B-based assistant that converts catalyst descriptions reported in journal articles into validated atomistic structures using ASE.

The system should support a scientist who provides a paper excerpt, DOI, figure caption, table, supplementary-information excerpt, or a manually summarized structure description. It should return:

1. A traceable structured specification.
2. An `ase.Atoms` object generated by approved ASE operations.
3. Structure files such as CIF, XYZ, POSCAR, and ASE trajectory files.
4. A report separating facts stated by the paper from assumptions and defaults.
5. Warnings or clarification questions when the paper does not contain enough information for a unique structure.

The first release is a structure-reconstruction tool, not a predictor of catalytic activity, reaction barriers, or the experimentally dominant surface.

## 2. Target catalyst structures

Version 1 should cover:

- Bulk crystalline catalysts and supercells.
- Low-index and stepped slabs described by Miller indices.
- Substitutional dopants, vacancies, and simple surface defects.
- Adsorbates and reaction intermediates placed on named sites.
- Supported metal atoms and small clusters on crystalline supports.
- Bimetallic surfaces and surface alloys.
- Simple nanoparticles with explicitly stated shape and size.

Defer these cases until later unless the paper supplies atomic coordinates:

- Amorphous materials.
- Poorly defined oxides or hydroxylated surfaces.
- Solvent/electrolyte interfaces with unknown configurations.
- Large reconstructed surfaces inferred only from microscopy images.
- Structures that require global optimization to identify atomic positions.

## 3. System architecture

```text
Paper text / SI excerpt / user description
                    |
                    v
         Qwen 4B structure parser
                    |
                    v
       CatalystSpec JSON + provenance
                    |
          schema and chemistry checks
                    |
                    v
         allow-listed ASE tool calls
                    |
                    v
              ase.Atoms
                    |
       geometry and consistency checks
                    |
                    v
 CIF / XYZ / POSCAR / trajectory + report
```

The LLM should normally generate `CatalystSpec` JSON rather than unrestricted Python. A deterministic dispatcher converts the specification into ASE calls. This makes outputs testable and avoids executing arbitrary model-generated code.
### 3.1 Agent implementation design

This document is the product, scientific-scope, and data-quality contract. The
implementation design for the cooperating agents, their permissions, hand-off
schemas, failure handling, and acceptance tests lives in
[`CATALYST_STRUCTURE_LLM_AGENT_DESIGN.md`](CATALYST_STRUCTURE_LLM_AGENT_DESIGN.md).

The non-negotiable boundary is: agents may extract evidence and propose a
versioned `CatalystSpec`; deterministic code performs Materials Project
retrieval, ASE construction, validation, file export, and any calculation. No
agent may execute arbitrary code, silently choose a scientifically material
missing value, or label an inference as a paper-reported fact.

### 3.2 Implemented local workflow

The local implementation lives in `src/ase_auto_build/ase_agent/`. It includes
the hand-off schemas, two bounded LLM roles, the policy gate, an injected
Materials Project resolver, the CatalystSpec dispatcher, validation, export,
failure records, and review packets. `ASE_catalyst_build` runs the two LLM calls
and deterministic pipeline without an interactive prompt:

```bash
ASE_catalyst_build --input request.json --out catalyst_requests
```

The input JSON contains only `request_id`, `request`, and `sources`. Each source
has a caller-assigned ID, locator, and text. The command writes one immutable
directory under the output root and returns a nonzero status for clarification,
unsupported work, pipeline failure, or environment failure.

The deterministic slice is gated by 100 immutable golden fixtures in
`tests/golden/` and the section 9 runner
`training/evaluations/run_vertical_slice_gate.py`, which reports all six
criteria at their thresholds (100/100 schema conformance, 89/89 build and export
round trips, zero writes outside a request package, zero unregistered tool
calls, zero fields without provenance, 11/11 ambiguities refused). Milestone 1's
exit criterion is therefore met for the supported scope, with the caveat that
the fixtures have not had a domain-expert review.

The journal command is an experimental, fail-closed baseline. The production r5
adapter was trained for direct ASE tool calling, not EvidenceLedger and
SpecProposal generation. Live prompt-only smokes on 2026-07-28 failed the journal
schema gate, so no journal-role adapter is promoted. The typed Python pipeline
can consume reviewed records while a dedicated journal-role corpus and adapter
are developed.

The dispatcher builds elemental and registered-prototype bulk/slab
structures, typed vacancies and substitutions, atomic or ASE-known molecular
adsorbates, simple elemental nanoparticles, and one supported cluster. A caller
may pass a resolved MP bulk parent through the Python API. Non-default compound
terminations, repeated coverage/coadsorption, molecular orientation controls,
lattice matching, and relaxation remain fail-closed until deterministic tools
and validation rules cover them.

## 4. Input contract

Each request should contain as much of the following as is available:

```json
{
  "request": "Build the Pt(111) catalyst with a 0.25 ML CO overlayer described in the paper.",
  "paper": {
    "title": "...",
    "doi": "...",
    "year": 2025
  },
  "evidence": [
    {
      "text": "A four-layer 2 x 2 Pt(111) slab ...",
      "source": "main_text",
      "locator": "Methods, page 4"
    },
    {
      "text": "CO was initialized at the atop site ...",
      "source": "supporting_information",
      "locator": "Figure S3 caption"
    }
  ],
  "requested_outputs": ["cif", "vasp", "xyz"]
}
```

For the initial version, paper text should be supplied by the user or a separate document-extraction stage. PDF parsing and figure interpretation should not be hidden inside the structure-generation model.

## 5. Output schema

Use a versioned schema. A minimal `CatalystSpec` is:

```json
{
  "schema_version": "0.1",
  "task_status": "ready",
  "material": {
    "formula": "Pt",
    "crystal_structure": "fcc",
    "lattice_parameters_angstrom": {
      "a": 3.92
    }
  },
  "model": {
    "kind": "surface",
    "miller_indices": [1, 1, 1],
    "supercell": [2, 2, 1],
    "layers": 4,
    "vacuum_angstrom": 15.0,
    "periodic_boundary_conditions": [true, true, false],
    "fixed_layers_from_bottom": 2
  },
  "modifications": [
    {
      "operation": "add_adsorbate",
      "species": "CO",
      "site": "ontop",
      "height_angstrom": 1.85,
      "anchor": 1
    }
  ],
  "provenance": [
    {
      "field": "model.layers",
      "value": 4,
      "evidence_type": "reported",
      "claim_index": 0
    },
    {
      "field": "model.vacuum_angstrom",
      "value": 15.0,
      "evidence_type": "assumed_default",
      "reason": "Vacuum thickness was not reported."
    }
  ],
  "clarification_questions": [],
  "requested_outputs": ["cif", "vasp", "xyz"]
}
```

This compact example abbreviates provenance. The policy gate requires a
`field_sources` entry and matching `CatalystSpec.provenance` entry for every
supplied structure value, including each modification field. Reported and
user-supplied values link to an `EvidenceLedger` claim; assumptions and derived
values carry a reason.

Allowed `task_status` values:

- `ready`: sufficient information exists to build a candidate structure.
- `needs_clarification`: a missing choice materially changes the structure.
- `unsupported`: the requested structure cannot be represented reliably by the current tool set.

Allowed provenance labels:

- `reported`: explicitly stated in the supplied source.
- `derived`: deterministically calculated from reported information.
- `assumed_default`: chosen by the system and clearly disclosed.
- `user_supplied`: added or corrected by the user.
- `ambiguous`: multiple interpretations remain possible.

Never label model knowledge or a guessed value as `reported`.

## 6. ASE tool layer

Expose small, typed, allow-listed operations instead of a general Python executor:

```python
build_bulk(spec) -> Atoms
build_surface(spec) -> Atoms
build_nanoparticle(spec) -> Atoms
make_supercell(atoms, matrix) -> Atoms
substitute_atom(atoms, selector, element) -> Atoms
remove_atom(atoms, selector) -> Atoms
add_adsorbate(atoms, adsorbate_spec) -> Atoms
add_supported_cluster(atoms, cluster_spec) -> Atoms
apply_constraints(atoms, constraint_spec) -> Atoms
validate_structure(atoms, validation_spec) -> ValidationReport
write_structure(atoms, formats, output_dir) -> list[str]
```

Each selector must be deterministic. Prefer identifiers such as element plus fractional position, layer index, symmetry-equivalent site, or a stable atom index produced by an earlier operation. Avoid vague selectors such as "the nearest atom" unless the selection rule and tie-breaking behavior are defined.

Use ASE for construction and file I/O. Use optional libraries where needed:

- `spglib` for symmetry checks.
- `pymatgen` for complementary structure conversion and surface analysis.
- `RDKit` for adsorbates supplied as SMILES.
- A separate calculator such as MACE, CHGNet, EMT, or DFT for relaxation. Relaxation results must be distinguished from the paper's reported geometry.

## 7. Missing-information policy

The assistant must ask for clarification when missing information changes chemical identity or topology, including:

- Element, composition, phase, or oxidation-state model.
- Surface orientation when several facets are plausible.
- Dopant identity or substitution site.
- Adsorbate identity, binding atom, or required adsorption site.
- Whether a reported structure is initial or relaxed.

Defaults may be used for computational-box details when explicitly reported as assumptions, for example:

- Vacuum thickness.
- Output format.
- Centering of a slab in the cell.
- Nonessential atom ordering.

When several scientifically reasonable reconstructions exist, generate separately named candidates rather than silently selecting one.

## 8. Training-data design

### 8.1 Training unit

Store supervised fine-tuning data as chat JSONL:

```json
{
  "messages": [
    {
      "role": "system",
      "content": "Extract a traceable CatalystSpec. Use only supplied evidence for reported facts. Return schema-valid JSON."
    },
    {
      "role": "user",
      "content": "Paper evidence: A four-layer 3 x 3 Au(111) slab was used. One surface Au atom was replaced by Pd. The bottom two layers were fixed. Build the structure."
    },
    {
      "role": "assistant",
      "content": "{\"schema_version\":\"0.1\",\"task_status\":\"needs_clarification\",\"material\":{\"formula\":\"Au\",\"crystal_structure\":\"fcc\"},\"model\":{\"kind\":\"surface\",\"miller_indices\":[1,1,1],\"supercell\":[3,3,1],\"layers\":4,\"fixed_layers_from_bottom\":2},\"modifications\":[{\"operation\":\"substitute\",\"element\":\"Pd\"}],\"provenance\":[],\"clarification_questions\":[\"Which top-layer Au site should be replaced by Pd?\"],\"requested_outputs\":[\"cif\",\"vasp\"]}"
    }
  ]
}
```

### 8.2 Dataset composition

Start with 5,000-20,000 executable, reviewed examples rather than a large unverified corpus:

- 25% bulk, phase, and supercell construction.
- 25% surfaces, steps, terminations, and constraints.
- 20% adsorbates and coverage interpretation.
- 15% dopants, vacancies, and alloys.
- 10% supported atoms/clusters and nanoparticles.
- 5% unsupported, contradictory, or insufficient-information cases.

Include English and Traditional Chinese requests, paraphrases, unit conversions, negative examples, conflicting evidence, and multi-turn corrections.

### 8.3 Data generation

1. Define the JSON schema and ASE operations first.
2. Create parameterized ASE templates that generate valid ground-truth structures.
3. Produce several natural-language descriptions for each specification.
4. Add real paper excerpts only when their license and intended use permit it.
5. Record DOI and source locator, but do not copy unnecessary copyrighted text into the dataset.
6. Execute every target specification and retain validation results.
7. Have a domain expert review a stratified sample and all ambiguous examples.

Synthetic data should vary structural parameters within chemically reasonable ranges. It should also contain deliberately incomplete prompts so the model learns to ask questions.

## 9. Qwen 4B training plan

Use supervised fine-tuning with LoRA or QLoRA first. Full-parameter training is unlikely to be necessary for schema extraction and tool selection.

Recommended sequence:

1. Baseline the unmodified instruct model with constrained JSON decoding.
2. Fine-tune on natural-language-to-`CatalystSpec` examples.
3. Evaluate on unseen papers, catalyst families, and wording styles.
4. Add failure examples and correction dialogues.
5. Optionally apply preference optimization to favor valid, traceable specifications over plausible but unsupported answers.

Training practices:

- Use the selected Qwen checkpoint's official chat template.
- Mask prompt tokens so loss is computed primarily on assistant output.
- Keep JSON keys stable and avoid multiple equivalent schemas.
- Use schema-constrained decoding during inference even after fine-tuning.
- Split train/test by paper and catalyst family, not by random individual records.
- Prevent nearly identical structures or excerpts from leaking across splits.
- Save adapter, tokenizer, schema version, dataset version, and training configuration together.

Initial experiments should compare rank 16 and 32 LoRA adapters. Tune learning rate, effective batch size, and sequence length using validation results; do not treat one configuration as universal. Structure correctness matters more than training loss alone.

## 10. Validation and evaluation

### 10.1 Deterministic validation

Every generated candidate must pass:

- JSON Schema validation.
- ASE construction without exceptions.
- Valid element symbols, finite coordinates, and nonzero cell volume where required.
- Correct atom counts and stoichiometry.
- Correct periodic boundary conditions.
- Minimum-distance checks using element-aware thresholds.
- Slab thickness and vacuum checks.
- Adsorbate-support separation and connectivity checks.
- Successful write/read round trips for requested formats.
- Constraint checks for fixed layers.

### 10.2 Model metrics

Track:

- Schema-valid output rate.
- Executable specification rate.
- Exact and tolerance-based field accuracy.
- Atom-count and composition accuracy.
- Cell-parameter and coordinate accuracy.
- Correct provenance classification.
- Clarification precision and recall.
- Unsupported-request detection.
- End-to-end structure success rate.

Do not use text similarity as the primary metric. Two different JSON strings can describe the same structure, and a fluent explanation can still produce the wrong catalyst.

### 10.3 Test-set policy

Create three held-out sets:

- `template_holdout`: familiar chemistry with unseen wording.
- `family_holdout`: unseen catalyst families or supports.
- `journal_holdout`: complete papers never used in data preparation.

Manually inspect failed structures in a 3D viewer and assign failure categories such as extraction error, ambiguity handling, incorrect ASE mapping, geometry collision, or source inconsistency.

## 11. Runtime behavior

The user-facing response should include:

```text
Status: ready / needs clarification / unsupported
Structure summary: composition, atom count, cell, PBC, surface, adsorbates
Source-backed facts: value + DOI/page/table/figure
Assumptions: value + reason
Warnings: ambiguity, collision, unsupported reconstruction
Files: CIF / XYZ / POSCAR / TRAJ
Reproduction record: schema version, model version, tool version, random seed
```

The system should preserve both the pre-relaxation and post-relaxation structures. Never overwrite the paper-derived candidate with a relaxed structure without recording the calculator, parameters, convergence status, and energy.

## 13. Delivery milestones

### Milestone 1: deterministic ASE prototype

- Finalize schema version 0.1.
- Implement bulk, surface, supercell, adsorbate, substitution, and vacancy tools.
- Add geometry validation and structure export.
- Hand-author 100 golden test cases.

Exit criterion: at least 95% of supported golden specifications build and pass deterministic validation.

### Milestone 2: prompt-only baseline

- Connect the base Qwen 4B instruct model.
- Add constrained JSON generation.
- Evaluate without fine-tuning.
- Catalogue extraction and ambiguity failures.

Exit criterion: establish reproducible baseline metrics on at least 300 held-out prompts.

### Milestone 3: QLoRA fine-tuning

- Curate and execute 5,000+ SFT examples.
- Train the first adapter.
- Compare against the prompt-only baseline.
- Add multilingual and clarification cases.

Exit criterion: at least 98% schema validity, 95% executable specifications, and a documented improvement in field and provenance accuracy.

### Milestone 4: journal reconstruction workflow

- Add paper/SI evidence ingestion.
- Store DOI and source locators per field.
- Support candidate generation for ambiguous structures.
- Run blinded review on unseen journal examples.

Exit criterion: a domain expert can reproduce, audit, and edit each generated catalyst without inspecting hidden model reasoning.

## 14. First implementation target

Build a narrow vertical slice before collecting a large dataset:

> Given a paper excerpt describing an elemental or binary crystalline slab, optional substitution/vacancy, and one adsorbate, produce a traceable `CatalystSpec`, build the `ase.Atoms`, validate it, and export CIF plus POSCAR.

Suggested golden examples:

- CO/Pt(111).
- O/Pd(100).
- N-doped graphene with a supported single metal atom.
- Oxygen vacancy on TiO2(110).
- Pt-substituted Au(111).
- Cu cluster on CeO2(111).

This vertical slice exercises the main scientific risks: extracting dimensions and units, mapping surface terminology to ASE, distinguishing reported values from assumptions, choosing adsorption or defect sites, and validating the resulting geometry.

## 15. Definition of done

The project is successful when a held-out journal description can be transformed into a reproducible structure package containing:

- A schema-valid and human-editable `CatalystSpec`.
- A successfully constructed and validated `ase.Atoms` object.
- Exported structure files.
- Field-level provenance tied to the supplied journal evidence.
- Explicit assumptions and unresolved ambiguities.
- Versioned records sufficient to regenerate the same pre-relaxation structure.
