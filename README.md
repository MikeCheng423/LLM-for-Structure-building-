# ASE_auto_build

A **fine-tuned local LLM that builds atomic structures from plain language.**
You describe the structure in words; the model plans a sequence of deterministic
[ASE](https://wiki.fysik.dtu.dk/ase/) tool calls; a bounded workspace executes
and validates every one of them; and the result is written to disk as a
ready-to-run DFT case.

No API key, no network — the model runs locally on your own GPU.

```bash
ASE_auto_build "Build a 2x2 Cu(100) slab with 4 layers and 12 A vacuum, then freeze the bottom 2 layers."
# -> structures/Cu16-b6a1d8b0/POSCAR
#    structures/Cu16-b6a1d8b0/structure.json
```

The model **only ever selects deterministic ASE tools and fills in their
arguments.** It never emits coordinates, never runs code, and never touches your
filesystem or network. A deterministic router narrows the tool registry per
request and **fails closed** on anything it cannot route — before a single tool
runs. Output paths are chosen by you and by the CLI, never by the model.

## Install

Requires Python ≥ 3.12 and a CUDA GPU for the model itself.

```bash
git clone https://github.com/MikeCheng423/LLM-for-Structure-building-.git
cd LLM-for-Structure-building-
python -m venv venv && source venv/bin/activate

pip install torch --index-url https://download.pytorch.org/whl/cu121  # match your CUDA
pip install -e ".[agent]"
```

That puts the `ASE_auto_build` command on your `PATH`. The argument handling
imports without the heavy dependencies, so `ASE_auto_build --help` works on a
CPU-only machine.

Point the CLI at a promoted LoRA adapter with `--adapter <dir>` or the
`ASE_AUTO_BUILD_ADAPTER` environment variable; by default it looks under
`training/runs/`. Use `--base-only` to talk to the frozen base model instead.

## Usage

| Mode | Command | Best for |
| --- | --- | --- |
| One-shot | `ASE_auto_build "Build an H2O molecule in a 12 A box."` | A single structure |
| Repeated | `ASE_auto_build -p "..." -p "..."` | A few structures, **one** model load |
| File | `ASE_auto_build --file requests.txt` | A planned batch, version-controlled |
| Piped | `echo "..." \| ASE_auto_build` | Generated by another script |
| REPL | `ASE_auto_build` | Exploring; keeps the model warm |

Each successful build writes one directory containing a `POSCAR` plus a
`structure.json` sidecar carrying the deterministic recipe, its hash, the tool
sequence, and structure invariants — so the same structure can be rebuilt later
without the model.

Useful flags:

- `--strict` — fail if a number you stated in the request was not actually used.
- `--json` — machine-readable output, for scripting.
- `-o DIR` / `$ASE_AUTO_BUILD_OUT` — where builds are written (default `structures/`).
- `--format FMT` — write extra formats alongside the POSCAR (e.g. `cif`, `xyz`).

The command uses **scriptable exit codes**: `0` built, `1` failed, `3` refused
(out of scope), `4` budget exhausted, `5` needs clarification, `6` environment
problem, `7` `--strict` mismatch.

Full walkthrough: **[docs/TUTORIAL_ASE_AGENT.md](docs/TUTORIAL_ASE_AGENT.md)**.

## What it can build

Bulk crystals and prototypes, molecules, surfaces and slabs (with vacuum and
layer constraints), nanotubes, supercells, substitutions and vacancies, and
atomic or molecular adsorption at named sites.

Requests outside that envelope are **refused before any tool runs** rather than
guessed at — the router's scope is the contract, and it is documented in
[training/CORPUS_RULE.md](training/CORPUS_RULE.md).

## Training

The adapter is a QLoRA fine-tune. The corpus is generated deterministically from
a rule (`training/generators/`), the model is trained with
`training/train_qlora.py`, and a candidate is only promoted if it beats the
incumbent on a held-out exact-match gate (`training/evaluations/`).

- **[training/HANDBOOK.md](training/HANDBOOK.md)** — the full training loop.
- **[training/USER_MANUAL.md](training/USER_MANUAL.md)** — running the built model.
- **[training/CORPUS_RULE.md](training/CORPUS_RULE.md)** — the request rule the corpus encodes.
- **[training/STATUS.md](training/STATUS.md)** — where the current iteration stands.

## Repository layout

```
src/vasp_auto/ase_agent/   the agent: CLI, controller, tool registry, validation, export
src/vasp_auto/             deterministic builders the agent's tools call into
training/                  corpus generation, QLoRA fine-tuning, evaluation, promotion
tests/                     GPU-free unit tests
docs/                      tutorial
```

> **Note on the import path:** the Python package is still importable as
> `vasp_auto` for historical reasons — this project began inside a VASP
> automation codebase. The command, the distribution, and the project are named
> `ASE_auto_build`.

## Development

```bash
pip install -e ".[dev]"
python -m pytest -q
```

The test suite is GPU-free: model interaction is exercised through scripted
fakes, so the whole suite runs on a laptop.
